## light 工作区搜索下载机制修复（light.cpp）

**问题**：`download <关键词> -s` 搜索下载机制几乎搜不到内容。

**根因**：Bing 有机搜索结果全部包装在 `https://www.bing.com/ck/a?...&u=a1<base64url>` 跳转链接中，原代码把含 `bing.com` 的链接直接全部丢弃 → 真实 URL 全部丢失；且只解析 `href="` 双引号、`IsValidDownloadPage` 要求 URL 必须含 download 等关键词（过度过滤）、域名黑名单用子串匹配会误伤。

1. 新增辅助函数块（约 309 行，位于 `class BingSearch` 之前）：

   - `ExtractFileNameFromUrl`：从 URL 提取文件名（去 query/fragment）
   - `GetNativeSystemArch`：GetNativeSystemInfo 检测本机架构 x64/x86/arm64
   - `ScorePackageForSystem`：安装包系统适配评分（<0 过滤，>=0 适配度；注意 x86_64 含 x86 子串，必须先判 x64——此 bug 被测试抓出后修复）
   - `IsInstallerPackageFile`、`ScoreDownloadPageLink`（页面相关度打分）
   - `FilterAndRankFileLinks`：系统过滤 + 同名去重（保留适配度最高）+ 适配度降序
2. `ExtractDownloadPageLinks` 重写：优先提取 `b_algo` 有机结果块（无则全页回退）、双/单引号 href、ck/a 解码、按相关度打分排序、上限 12 个页面

## 下载链接提取增强（2026-10-25 下午，备份 light.cpp.bak_pre_anchortext）

**用户实测反馈**：`D "Visual Studio" -s` 搜索成功（找到 5 个页面，第一阶段修复生效），但第二阶段报"在所有下载页面中未找到文件链接"。

**根因**：文件链接提取只匹配带扩展名的 URL（.exe/.zip 等）。现代下载页大量使用无扩展名下载入口——实测 VS Code 下载页（code.visualstudio.com/download）的 29 个下载按钮全是 `/thank-you?dv=win64user&build=stable` 形式，锚文本是 "User Installer (x64)"、".zip (x64)" 等；thank-you 页本身纯 JS 渲染，静态抓取拿不到真实文件地址。

**修复内容**（light.cpp）：
1. 新增 `ExtractAnchors`：解析 `<a>` 的 href + 可见文字（支持单双引号、去嵌套标签、压空白）；`HtmlEntityDecode`（&amp; 等）
2. `IsDownloadEntryUrl`：识别 `/download?`、`/sha/download`、GitHub `/releases/download/|latest/download/`、`/archive/refs/tags/` 等无扩展名下载入口
3. `TextSuggestsDownload`：锚文本含 download/下载/installer/setup/.zip 等特征即纳入候选
4. `FileLinkInfo` 增加 `displayName`；系统评分改为 `displayName + " " + url` 合并评分（架构标记常在文字里，如 ".zip (x64)"）；`selectedName` 成员 + `GetSelectedName()`
5. 去重键区分：直链按 fileName（过滤镜像/同文件多版本），无扩展名入口按 displayName（防止 /thank-you 同路径段把不同 dv 变体折叠成一个——此 bug 由 Python 实测抓出）
6. 自指链接检查改为大小写不敏感且在相对链接解析之后（页面同时有 /download 和 /Download 两个自指）
7. `DeriveDownloadFileName`：无扩展名时依次尝试 Content-Disposition（WinHTTP HEAD，UTF-16→UTF-8 用 WideCharToMultiByte，避免 C4244 警告）→ 展示名+文字推断扩展名 → downloaded_file；`SanitizeFileName` 清理非法字符
8. 下载无扩展名入口时打印提示（可能是网页，需浏览器打开）

**验证**：
