# 2026-11-26

## MCLauncher：实例模型 / 下载落盘 / 启动入口 全面对齐 HMCL

用户诉求（7 项）：模组下载保存位置、光影/世界/游戏版本下载、版本检查逻辑（删了文件还显示已安装）、
首页只留一个启动按钮 + 弹窗、版本选择像 HMCL 实例列表、皮肤头像模糊、装加载器后多出第二个游戏。

### 关键发现（对照 D:\Desktop\HMCL-main）
- HMCL 3.6 已不是「一个版本目录 = 一个游戏」：`GameInstanceManifest.patches` + `GameInstanceAnalyzer`，
  加载器是**装进同一个实例的组件**（`updateInstanceAsync` / `installComponent`），不会新建版本目录。
- 实例列表 = `repository.getDisplayInstances()`，即 `versions\*` 的扫描结果（没有第二份注册表），
  并过滤 `manifest.isHidden()`。→ 所以「删了目录还在列表里」在我们这边是自建 registry 的问题。
- 实例内目录：`getModsDirectory()` = runDir/mods、`getResourcePackDirectory()` = runDir/resourcepacks、
  `getSavesDirectory()` = runDir/saves；shaderpacks 同理。

### 本轮实现
- `MlcData`：新增 `SyncWithDisk()`（每次 Rebuild 前对账，剔除被删版本、补登记新版本、
  合并同文件夹同版本的重复记录、当前实例被删则回落）、`IsVisibleInstance()` / `HiddenParentCount()`
  （被别的版本 inheritsFrom 引用的原版只算组件）、`AdoptLoaderVersion()`（装/升级加载器把同一实例换版本）、
  `ParentOf()` / `JsonIdOf()` / `DefaultFolder()`（= `<Exe>\.minecraft`）、`NormalizePath()` / `SamePath()`。
  `m_parents` 缓存用 **NormalizePath 做 key**（踩过坑：一边 `D:/x` 一边 `D:\x` 导致查不到）。
  卸载加载器退回 `inheritsFrom` 原版，游戏不消失。
- 默认游戏目录从 `Data\mlc\games\default` 改成 `<主程序>\.minecraft`（HMCL 便携模式）。
- 下载页：内容分类新增「下载到」实例下拉（`m_dlInstIds`），并显示解析后的完整路径；
  Modrinth 的 `game_versions` 过滤改用 `mc::baseVersionId()` 回溯原版（之前拿 loader 版本号去查，一条都匹配不到）。
- 首页：只剩一个「▶ 启动游戏」→ `m_showLaunchDlg` 弹窗（实例行 + 账号下拉 + 启动/取消）。
- 版本选择：左「游戏目录」抽屉 + 右实例行 + 搜索 + 「显示原版组件」+ 工具栏。
- 皮肤：`InterpolationModeNearestNeighbor`（头像 8×8→40px 不再糊）。
- 验证：`tools/t_sync.cpp`（隐藏父版本 / 删除后消失）、`tools/t_adopt.cpp`（装加载器只留一个游戏）离线跑通；
  `tools/check.ps1` 单文件编译检查。
- 已部署：`D:\YX\light\x64\Release\Cache\gui\dll\YXG_MinecraftLauncher.dll`（旧版备份 `.bak_20261126`）。
