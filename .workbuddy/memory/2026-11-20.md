# 2026-11-20 — MCLauncher 2.0 实例化改造

## 本次改动范围
项目 `D:\YX\MCLauncher`（light 的附属插件 DLL）。原样备份在 `D:\YX\MCLauncher_备份`（29 个源文件 + 工程/脚本）。

## 架构变化（2.0「实例」模型）
- 新增 `src/MlcData.h/.cpp`：`Data\mlc` 数据层。主程序目录 = `GetModuleFileNameW(NULL)` 所在目录（即 light.exe 处）。
  存储：`config/global.json`、`games/registry.json`、`games/<id>/settings.json`、`cache/covers`、`backups`、`logs`。
  `Instance = folder + versionId`；`isolate` 默认 **关**（沿用 .minecraft 根），隔离时 dataDir = `versions/<id>`。
  名称规则：任意语言字母数字 + 仅允许 `_`；自动名直接用版本 id（含点号）。
- 新增 `src/ContentLib.h/.cpp`：模组/资源包/光影/世界/原理图扫描 + 封面提取（jar 内 fabric.mod.json/quilt/mods.toml/assets 图标、pack.png、世界 icon.png）+ 启停（.disabled / options.txt 的 resourcePacks）+ Modrinth 双语搜索（中文关键词字典翻译后并行搜索合并）。
- UI 拆成 4 个文件：`Ui.cpp`（窗口/输入/事件/EDIT 覆盖层）、`UiPages.cpp`（布局）、`UiPaint.cpp`（绘制）、`UiActions.cpp`（交互/异步）。`UiNav.h` 放导航表与布局常量。
- `LauncherApp` 改为实例模型：`launchInstance(id)`（含完整性检查→自动修复→备份存档→启动）、`startInstall(folder, versionId, loaderType, loaderVersion, name)`、`startIntegrityCheck`。
- `LauncherCore` 新增 `mc::checkIntegrity()`（version json / client jar / libraries / natives / assets）。

## 修掉的真实 Bug（重要）
1. **Zip.cpp 中央目录解析错位**：ZIP 的修改时间/日期各 2 字节，旧代码按 4+4 读，导致 ForEach/ReadEntry/ExtractAll 全错位
   → 模组标题、模组封面、世界 zip 导入全部失效。已重写 Zip.cpp（统一 readCentralDir、ZIP64 回退、数据描述符用中央目录尺寸兜底、
   分隔符 `\`→`/` 归一、路径穿越防护）。`Zip::ReadEntry` 现在对 Compress-Archive 生成的 zip 也能读。
2. 首页版本下拉不继承当前选择 → 点启动必报「请先选择版本」。
3. 隔离目录原本指向 `versions/<id>\data`（不符合 HMCL）。
4. 模组/存档页永远读全局目录，忽略实例与隔离。
5. 后台线程直接写 UI 正在读的 vector → 改为事件带 JSON，在 UI 线程落地。
6. Ui 析构不销毁窗口（插件重载残留）。
7. 输入无输入法 → 隐藏原生 EDIT 覆盖层（`m_editOverlay`）。
8. 按钮文字固定白色，浅色主题看不清 → 按底色亮度选黑白；主行动色固定 `RGB(46,125,50)`。
9. 侧边栏/按钮 emoji 在本机缺 emoji 字体时是豆腐块 → 全部移除，侧边栏改圆点 + 账号名首字。
