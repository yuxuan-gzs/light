### 本轮修复的缺陷
1. **预处理器 `Ev::cur()` 把 `Tok::End` 当有效 token** → 所有 `#if` 都被判为"尾部垃圾"而恒为 false。已让 `cur()`/`bump()` 忽略 End。
2. **`defined(NAME)` 括号形式不支持**（原实现只认 `defined NAME` / `defined NAME()`）→ `defined()` 求值恒失败。已补括号分支。
3. **C++ `namespace` 被当成 Java `package`**（`parseNamespace` 写 `prog.packageParts`）→ 单文件输出里出现 `package probe;` 且持有者类 `public` 导致 javac 报错。已改为不写 packageParts（改用新成员 `nsNames_` 供 `tryQualifiedMethod` 判定），持有者类改为非 public。
4. **命名空间内的全局变量/自由函数无法被同类实体引用** → 新增 `ClassDecl::ns`，在 `E` 上加 `nsHolder` + `GenCtx::nsMembers`，用 `qualName()` 自动补 `Holder.` 前缀（Name 表达式与裸名调用两处）。
5. **枚举常量裸引用未限定** → `GenCtx::enumConstOwner` + `E::inEnumBody`，裸名发射为 `Enum.CONST`。
6. **枚举→整型 C 风格转换生成非法 Java** → 改写为 `.ordinal()`。
7. **`m["a"] = 1`（std::map 下标写）生成 `m.set(...)`** → Map 用 `.put`，List 仍用 `.set`。
8. **`std::string("x")` 生成 `string("x")`** → 单参数改为 `String.valueOf(...)`，多参数警告并发射 `""`。
9. **未知全大写导出宏（如 `PLUGIN_API`，定义在未展开的头里）导致整条声明失败** → 新增 `looksLikeExportMacro()` / `skipExportMacro()`，在 `parseFreeFunction` 与 `parseMember` 入口跳过并警告。

### 新增资产

# 2026-10-30（续2）MCLauncher：HMCL 兼容 MC 启动器 DLL（新 VS 项目）

在 `D:\YX\MCLauncher` 新建标准 VS 工程，C++20 编写 Minecraft 第三方启动器（HMCL 格式），编译为 YXG GUI 扩展 DLL。

## 用户需求与决策
- 功能范围=完整启动器；界面=「修改 YXGui 适配」；「HMCL 格式」= 与 HMCL 互通的标准 Mojang version JSON + .minecraft 目录布局（已上网核实 HMCL/BMCLAPI/离线 UUID）。

## 架构
- `YXG_MinecraftLauncher.dll`（x64，/std:c++20 /MT /utf-8 /Zc:char8_t-）：导出 YXG ABI（YXG_RegisterPlugin/UnregisterPlugin/GetExtensionInfo），注册自定义命名空间 `mc.*` 共 22 个 JS API。
- 模块：Json（自写解析器）、Crypto（CNG MD5/SHA1 + 离线 UUID）、Http（WinHTTP 带进度下载+sha1 校验）、Zip（zlib inflate 解压 natives）、LauncherCore（版本清单/版本模型/规则/参数构建/安装编排）、MsAuth（微软设备码→XBL→XSTS→Minecraft）、JavaDetect、McApi（状态机+异步任务）。
- 依赖：静态链接 zlib（`D:\zlib-1.3.2\build\Release\z.lib`）。输出 `bin\x64\Release\YXG_MinecraftLauncher.dll`（626,688 字节）。
- 配套 UI：`ui/plugin.json` + `ui/main.js`（QuickJS + 原生控件，HMCL 风深色主题）。

## 宿主适配（修改 YXGui，支持自定义命名空间）
- ExtensionManager.h/.cpp 加 `GetNamespaces()`；GuiDllStore.h/.cpp 加 `GuiDllPluginHost::GetNamespaces()`；JSPlugin.h/.cpp 加 `GetExtNamespaces()` + InitRuntimeAndApis 创建自定义命名空间全局对象 + 新增 `RegisterExtNamespaceApis`。这样扩展 DLL 注册的 `mc.*` 自动挂到 JS 全局对象。3 个改动的 .cpp 已用 cl /c 验证 0 error。

## 关键 bug 修复（核查中发现）
1. `Library::artifact`（maven 名）与 `Artifact artifact`（主 jar 结构）重名 → maven 字段改名 `artifactName`。
2. `os.version` 规则误用 `std::regex_match`（全匹配），Mojang 规则 `^10\.` 是部分匹配 → 改 `std::regex_search`。
3. 纯 natives 库（如 lwjgl-platform，无主 jar）被误加入 classpath 并下载不存在的 jar → `hasMainArtifact()` 改为「有 artifact.url 或（无 natives 且无 classifiers）」。
4. `fs::path::u8string()` C++20 返回 char8_t 串 → 用 `/Zc:char8_t-` 全局关闭。
5. `std::min`/`getenv` 被 windows.h min 宏/CRT 安全告警（/sdl 下变 error）→ 加 `/D NOMINMAX /D WIN32_LEAN_AND_MEAN /D _CRT_SECURE_NO_WARNINGS`。
6. 宏 MC_END 后漏函数收尾 `}`；`Plugin* p` 与局部 `mc::InstallProgress p` 同名遮蔽；`mc_register_all` 块作用域 extern 作用域错 → 改头文件命名空间级声明。
