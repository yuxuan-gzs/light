## 皮肤：设置 / 上传正版 / 从正版拉取 / 披风（MCLauncher 插件）

### 需求
「怎么设置皮肤？正版账号设置后推送到服务器；预览正版账号皮肤时从远程拉取；允许自定义离线/正版的皮肤、披风路径；操作方法和 HMCL 一样。」

### HMCL 的做法（已核源）
- `MicrosoftService.uploadSkin`：`POST https://api.minecraftservices.com/minecraft/profile/skins`，
  `Authorization: Bearer <MC access token>`，`HttpMultipartRequest` → `variant=classic|slim` + `file`（image/png）。
- 拉取：`https://sessionserver.mojang.com/session/minecraft/profile/<uuid32>` → `properties[0].value`（base64）
  → JSON `textures.SKIN.url`（+ `metadata.model=slim`）/ `textures.CAPE.url`。
- HMCL `Skin` record：type（DEFAULT/ALEX/STEVE/…/LOCAL_FILE/LITTLE_SKIN/CUSTOM_SKIN_LOADER_API/YGGDRASIL_API）+
  `textureModel` + **`localSkinPath` 与 `localCapePath` 分开两个路径**。
- 注意：Mojang 没有「上传披风」API，披风只能本地引用/已有披风切换 → 本次披风只做本地路径。

### 实现
- 新文件 `src/SkinNet.h/.cpp`：
  - `UploadToMojang(token, png, slim, err)` 手拼 multipart（boundary、Content-Disposition），
    走 `http::PostWithHeader`；401/403 提示重新登录；其他错误取 `errorMessage`。
  - `FetchFromMojang(uuid, skinDest, capeDest, &slim, &hasCape, err)` 一次 profile 请求同时拉皮肤+披风；
    纹理 URL 是 `http://textures.minecraft.net/...`，统一改 `https://` 防 301。
  - `CompactUuid()`：去横线 + 转小写。
  - 自带 base64 解码（项目原本没有）。
- `src/Http.cpp` 新增 `PostWithHeader(url, body, contentType, headerLine, timeout)`（复用 static `DoRequest`）。
- `src/Skin.cpp`：
  - `Get(path, slim)`：缓存 key = `路径 + \x01 + wide|slim`；slim 时手臂 3×3、位置 ±5.5。
  - `GetCape(path)` / `ProbeCape()`：64×32 布局，(1,1) 外侧 10×16、(12,1) 内侧 10×16。
  - `DrawCharacter(g, model, cape, ...)`：披风贴背后 z=-2.3→-3.6（底部外飘），`FaceDraw::noCull` 双面绘制。
- `MlcData`：`AccountRec` 加 `skinPath / cape / capePath / skinModel / skinRemoteAt`；
  `Store::EffectiveSkin / EffectiveCape / IsSlim`（自定义路径优先于 `skins\` 托管文件）。
- UI（账号页右侧，选中账号即生效）：
  预览 258px + 四行按钮：`选择皮肤|移除`、`经典|纤细`、`皮肤路径|披风…`、`上传正版|正版同步`（离线账号显示一行提示）。
  底部 `acc.code/acc.tip/acc.offlinetip` 宽度收窄到 `listW`，避免压住右侧按钮列；卡片高度改 `m_height-36`。
- 事件协议（`Ev::Info` 前缀）：`__skinfetch__:<key>` 触发拉取 → 后台 → `_skinres:<key>|ok|slim|cape|err`；
  `_skinup:<key>|ok|err`。选中 msa 账号且本地无皮肤时 BuildAccount 末尾自动 post 一次，
  `m_skinAutoKey` 保证每个账号每次运行只自动试一次。
- 上传前若 `expiresAt` 过期且是当前账号，先 `App::refreshAccount()` 再取新 token（避免必然 401）。

## 第三轮：账号切换修复 + 加载器安装重写（HMCL 式）

### 账号「无法切换」的根因（我上一轮引入的 bug）
- 点账号列表行时调了 `Rebuild()`，而 `BuildAccount` 里 `lst.selIdx = sel`（sel = **当前账号**索引），
  于是选中项被弹回当前账号 → 「使用选中账号」永远切不动。
- 修复：新增 `Ui::m_accSel` 记住用户点的行；`BuildAccount` 优先用它，无效才回落到当前账号；
  `acc.use/del/storage/新登录` 时相应维护；`List` 点击只更新 m_accSel。

### 加载器「永远失败」的多个真因
1. `RefreshLoaderVersions` / `loader.install` 直接用 `instance.versionId`。实例本身是
   `fabric-loader-0.16.5-1.20.1` 时，meta 请求/Forge 版本列表必 404。
   → 新增 `mc::baseVersionId(versionsDir, id)` 沿 inheritsFrom 回溯原版。
2. Fabric/Quilt 没选版本（`lv` 空）时 profile URL 变成 `.../loader/1.21.11//profile/json` → 404。
   → `loader::Install` 在 loaderVersion 为空时自己 `FetchVersions` 取最新 stable。
3. Forge/NeoForge 硬塞 `resolveJava(Instance{}, 17)`：1.12.2 的 installer 在 17/21 下必崩。
   → `JavaMajorForMc` + `PickInstallerJava`（精确版本优先，≤1.16.5 必须 Java 8）。
4. installer 只给退出码，无诊断。→ 输出重定向到临时文件/`logs/loader-install.log`，失败带异常行。

### 按 HMCL 重写 Forge/NeoForge 安装（新文件 src/ForgeInstall.cpp）
HMCL 从不运行 installer 的 main。它读 `install_profile.json`：
- 含 `spec` = 新格式：复制 installer 内 `maven/<path>` 的库 → 下载其余 → 读 `version.json` 写版本 →
  按 `processors` 逐个 `java -cp ... MainClass args`；`sides` 不含 client 跳过；outputs 已存在则跳过。
- 含 `install`+`versionInfo` = 旧格式（≤1.12.2）：从 installer 解压 universal jar 到 libraries，
  `versionInfo` 直接写版本 JSON，**不需要 Java**。
- `DOWNLOAD_MOJMAPS`（纯下载）改成读版本 JSON 的 `downloads.client_mappings` 走 BMCLAPI 镜像。
- data 值形如 `{client: "...", server: "..."}`（按 side 取）；`/xxx` 是 installer 内文件要解压到临时目录；
  `[maven:coord:cls@ext]` 展开成 libraries 下路径；`{VAR}` 用 vars 替换。
- 实测：官方 installer 用 Java 21 跑 1.21.11-61.2.5 **成功**（8m14s，大半耗在 DOWNLOAD_MOJMAPS），
  产物 `forge-1.21.11-61.2.5-client.jar` sha1=f2a31288... 与 profile 一致 → 证明 processors 命令正确。
- 客户端只需 3 个 processor：DOWNLOAD_MOJMAPS、ForgeAutoRenamingTool、binarypatcher。

### 「安装加载器后会出现一个新版本」
- 这是加载器安装的固有行为：versions/ 下新建 `原版id-加载器id` 复合版本（inheritsFrom 指向原版），
  原版文件保留。Forge 官方 installer 也这么做。
- 改进：安装后 `EnsureInstance` 复用同名实例 + `SetCurrent` 自动切过去；
  提示改为「已新建版本 xxx（原版保留），并切换为当前游戏」；重复安装不再产生第二个游戏。
